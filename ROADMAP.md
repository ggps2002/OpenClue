# OpenClue roadmap

Each scheduled run takes the first unchecked milestone, builds a working slice, and records progress here.

## Milestones

- [x] 1. **Foundation.** Workspaces, client and server skeletons, `server.ts`, Prisma + SQLite, all root scripts working, README. Email/password auth (bcrypt, JWT in an httpOnly cookie) with sign-up, sign-in and sign-out. A public landing page with original copy describing the product. A signed-in app shell with sidebar navigation and an empty dashboard.
- [x] 2. **Projects and media.** Create, rename and delete projects. Upload video, images, PDF and slide files (multer → StorageService). A per-workspace media library. A project detail page.
- [x] 3. **Browser screen recording.** Record screen + mic with getDisplayMedia + MediaRecorder from inside the app (a `ScreenRecorder` class), capture click positions and timestamps during recording (for auto-zoom later), and upload the result into a project.
- [x] 4. **Transcription and AI script.** Transcribe a recording's audio. Claude rewrites the rough narration into a clean script split into timed segments, which the user can edit.
- [x] 5. **AI voiceover.** Generate TTS audio per script segment, with a voice picker, synced to segment timing, and the option to regenerate one segment.
- [ ] 6. **Video editor.** A timeline with scenes, tracks and clips (a `Timeline` model class): trim, split, reorder; text, shape and image overlays with keyframed position, scale and opacity; transitions between scenes; automatic zoom/spotlight effects from recorded click data, which the user can edit; a live preview player.
  - [x] 6a. `Timeline` model class (scenes, audio tracks, clips): split, trim, reorder, mute, add/remove; persisted per project (`Timeline` table), seeded from a project video + the voiceover track; editor page with undo/redo.
  - [x] 6e. Live preview player (`TimelinePlayer` class) that plays the edit across scenes with the audio tracks in sync.
  - [x] 6b. Text, shape and image overlays on their own tracks, with keyframed position, scale and opacity (and preview rendering).
  - [ ] 6c. Transitions between scenes (fade, slide, …) in the model and the preview.
  - [ ] 6d. Automatic zoom/spotlight effects generated from recorded click data, editable on the timeline.
  - [ ] 6f. Editor ergonomics: drag handles to trim on the strip, timeline zoom, dragging audio clips.
- [ ] 7. **Captions.** Auto-generate captions from the script/voiceover, with brand-styleable caption presets. Export SRT and VTT.
- [ ] 8. **Export and rendering.** A server-side render of the timeline to MP4 with ffmpeg through an in-process job queue class with progress polling, plus GIF export. Track export minutes per user each month.
- [ ] 9. **Documentation from video.** Turn a video into a step-by-step guide: extract key frames as screenshots (ffmpeg) and have Claude write the steps. An editable article view, with export to Markdown, HTML and PDF.
- [ ] 10. **Translation.** Translate the script, captions and on-screen text into many languages with Claude, re-voice with TTS, and keep a language switcher per project.
- [ ] 11. **Slides/PDF/doc to video.** Turn an uploaded deck or document into scenes with narration.
- [ ] 12. **Prompt to video.** The user writes a prompt and can attach reference files. The app asks clarifying questions (audience, goal, style), then generates a draft video (scenes, on-screen text, simple motion, voiceover) that opens in the editor.
- [ ] 13. **Brand kit and style templates.** A brand kit (logo, colors, fonts) applied to captions and overlays. Save a video's structure, style, pacing and audio as a reusable style template and apply it to new videos.
- [ ] 14. **Collaboration.** Workspaces with members and roles (owner/editor/viewer), invites, comments pinned to timeline timestamps, review/approval status, and view-only share links.
- [ ] 15. **Plans and usage.** A pricing page (Free with 10 export minutes a month, Solo, Business, Enterprise) and plan limits enforced on export. Keep billing as a stub module behind an env flag (Stripe only if `STRIPE_SECRET_KEY` is set).
- [ ] 16. **Polish.** Responsive layouts, accessibility pass, empty and error states, an end-to-end test of the core flow (record/upload → script → voiceover → export → docs).

Stretch (only after 1–16): AI presenter avatars, an MCP server exposing projects to AI clients, a Chrome extension recorder, SSO.

## Decisions

- **2026-10-15 — Schema changes via `prisma db push`, not migrations.** Keeps SQLite zero-setup and the schema provider-agnostic (migration SQL is provider-specific). Revisit when moving to Postgres in production.
- **2026-10-15 — Test DB reset by deleting the file.** Prisma's CLI blocks `db push --force-reset` when run by an AI agent, so `server/tests/global-setup.ts` deletes `prisma/test.db` and runs a plain `db push`. Do not try to bypass Prisma's consent check.
- **2026-10-15 — Express 5.** Native async error propagation, so controllers need no async wrapper.
- **2026-10-15 — Tailwind v4 via `@tailwindcss/vite`.** No `tailwind.config.js`/`postcss.config.js`; theme tokens live in `client/src/index.css`. Vitest config lives inside `client/vite.config.ts` (one config per package).
- **2026-10-15 — `bcryptjs`** (pure-JS bcrypt) instead of native `bcrypt` to avoid native builds.
- **2026-10-15 — Personal workspace on sign-up.** Every user gets a `Workspace` + `Membership(role="owner")` at sign-up so media/projects can be workspace-scoped from milestone 2; roles are strings (`owner|editor|viewer`) for Postgres/SQLite portability.
- **2026-10-15 — Server is CommonJS** (`tsc` → `server/dist/src/server.js`); `server/tsconfig.json` also includes `tests/` so typecheck covers them. The root ESLint flat config is `eslint.config.mjs`.
- **2026-10-15 — Server tests in `server/tests/`, client tests colocated.** Server tests share one SQLite DB and run without file parallelism.

- **2026-10-15 — Access checks via `requireWorkspaceRole()`** in `server/src/lib/access.ts`, called by services (not middleware) because the workspace is often derived from a loaded record. Roles rank viewer < editor < owner.
- **2026-10-15 — Module routers mount at `/api`** and declare full paths (`/workspaces/:id/projects`, `/projects/:id`); `requireAuth` is applied per route so unknown `/api` paths still 404.
- **2026-10-15 — Recording metadata lives in its own `Recording` table**, keyed by `mediaAssetId`, with clicks as Prisma `Json` (supported on both SQLite and Postgres). Media DTOs include only the small summary (`durationMs`, `clickCount`) via `mediaInclude`; full clicks come from `GET /api/media/:id/recording`.
- **2026-10-15 — Clicks are stored normalised** (`x`, `y` in 0..1 of the page viewport, `t` in ms of recorded time excluding pauses) together with the shared surface (`browser`/`window`/`monitor`), so the editor can decide how reliable the mapping to the video frame is.
- **2026-10-15 — `ScreenRecorder` takes a `RecorderEnvironment`** (mediaDevices, MediaRecorder, click target, clock) defaulting to browser globals, so tests run with fakes (`features/recorder/test-fakes.ts`) without a DI layer.
- **2026-10-15 — Media files are served through the API** (`/api/media/:id/file`, cookie auth), never as static files, so access checks always apply.

- **2026-10-16 — AI clients live in `server/src/lib/`** as concrete classes (`ClaudeClient`, `SpeechClient`) with an `isOnline` flag; services decide their own offline placeholder. Tests swap behaviour by subclassing (`FakeClaude extends ClaudeClient`) or injecting `fetch`, not via interfaces.
- **2026-10-16 — Claude JSON via structured outputs** (`output_config.format` json_schema), not forced tool use (forced `tool_choice` is rejected by current models). Responses are re-validated with zod.
- **2026-10-16 — Scripts are stored as one JSON array of `{ id, startMs, endMs, text }` per project/language** and saved wholesale on edit. Voiceover (milestone 5) keys audio by segment id.
- **2026-10-16 — Speech-to-text goes over plain `fetch` + `FormData`** to the OpenAI REST API (no extra SDK dependency); model from `STT_MODEL`.

- **2026-10-16 — Voiceover clips in their own table** (`Voiceover` per script, `VoiceoverClip` per segment id). Each clip stores the text, timing and voice it was made from, so "stale" is a plain comparison and "update changed" only re-voices what changed. A clip whose words and voice are unchanged and that still fits a moved slot is just retimed (no TTS call).
- **2026-10-16 — Fitting speech to segments:** TTS longer than its slot is sped up with ffmpeg `atempo` up to 1.25×; anything still too long is kept and reported as `overflowMs` so the user shortens the text (speech is never cut). A mixed track (`adelay` + `amix`, covering the whole script) is rebuilt after every generation and is what the editor/export will use.
- **2026-10-16 — Generated per-project files live under `projects/<projectId>/`** in storage; `ProjectService.delete` removes that prefix (`StorageService.removeDir`). Renders and exports should use the same prefix.

- **2026-10-16 — The timeline is one JSON document per project** (`{ version, scenes, tracks }`), validated by `timelines.schema.ts` on save and mirrored by the client `Timeline` class. Scenes are cuts (`mediaId`, `inMs`, `outMs`) played back to back; tracks are layered over them with clips placed at a timeline `startMs`. New features (overlays, transitions, zooms) extend the document; bump `version` only for breaking changes.
- **2026-10-16 — The `Timeline` model and `TimelinePlayer` live on the client** (OOP in non-UI classes). The model is immutable, so undo/redo is a list of past values. The server stays the authority on validity (sources, ranges) and will render the same document in milestone 8.

- **2026-10-16 — Overlays are `overlay` tracks in the timeline document** (tracks are a union on `kind`; `version` stays 1 because the change is additive). Each overlay clip has `startMs`/`durationMs`, a box (`width`/`height`) and content (`text | shape | image`), and is positioned in the **16:9 output frame** using fractions (x/y = box centre, may go off-frame for slide-ins), so the preview and the milestone 8 render share one coordinate system. Text size is a fraction of frame height (CSS `cqh` in the preview).
- **2026-10-16 — Keyframes are relative to the overlay's start** (`t` ms, sorted, at least one). A single keyframe means a static overlay, so editing values or dragging changes it; with several, edits go to the keyframe under the playhead (±50 ms) or add one there. `easing` on a keyframe shapes the move to the next one (`linear` or smoothstep `easeInOut`). Keyframe maths lives in `client/src/features/editor/overlays.ts`; the server only validates.

## Progress log

### 2026-10-16 — Milestone 6 (Video editor): overlays with keyframes (6b)
- Server: `timelines.schema.ts` gains `overlay` tracks (text/shape/image content, box, keyframes with order and range checks); `TimelineService` lists project images as sources (no probing) and rejects image overlays whose file isn't an image of the project (and image files used as audio).
- Client: `overlays.ts` (types, `valuesAt` interpolation, `setValuesAt`, add/remove/update keyframes, `setDuration`, `fadeInOut`, `createOverlay`), `Timeline` gains `audioTracks`/`overlayTracks`, `addOverlay` (top-most free overlay track, else a new one), `updateOverlay`, `overlaysAt`, `setTrackHidden`; removing a track's last overlay removes the track; durations include overlays. `OverlayLayer` draws overlays over the preview (drag or arrow keys to position, which keyframes at the playhead); `OverlayInspector` edits content, size, timing, values at the playhead, keyframe list (go to, easing, delete), fade in/out, hide track, remove. Overview offers "Add text / shape / image" at the playhead. Overlay rows on the timeline strip show keyframe markers. `NumberField` and `ColorField` (one undo step per pick) in `fields.tsx`.
- Tests: 88 server (+2: overlay save/image checks, keyframe validation), 68 client (+7: overlay maths, Timeline overlay ops, editor add/edit/nudge/fade/save flow). typecheck/lint/test/build green; production build smoke-tested in headless Chromium (WebM + PNG upload → seed → add text → drag → save → reload keeps the position).
- Next: 6c transitions between scenes (model + preview), then 6d auto-zoom from clicks, 6f ergonomics (drag handles, timeline zoom, dragging clips/overlays on the strip).
- Known issues: overlays can't be dragged along the timeline strip yet (set start in the inspector); fonts are the app font until the brand kit (milestone 13) adds font choices; image aspect ratio is kept inside the box (`object-contain`) so a box much wider than the image leaves empty space.

### 2026-10-16 — Milestone 6 (Video editor): timeline model, persistence, editor and preview (6a, 6e)
- Prisma: `Timeline` (one per project, JSON document, cascades with the project); `MediaAsset.durationMs` (probed lazily with ffmpeg the first time the editor needs it; recordings use their stored duration).
- Server: `timelines` module — `GET/POST/PUT /api/projects/:id/timeline`. GET returns the document (or null), the project's video/audio sources with durations, the voiceover track and the caller's role. POST seeds one scene of a project video (default: the video the script was written from, else the newest) plus a "Voiceover" audio track when there is one (the scene is then muted). PUT validates the structure (zod: unique ids, min 100 ms cuts, limits) and that every scene/clip uses a file of this project and ends inside it.
- Client: `Timeline` (immutable model: placements, `sceneAt`, split/trim/move/rename/mute/add/remove scenes, move/remove/mute audio), `TimelinePlayer` (one `<video>` switching sources per scene + one audio element per clip, wall-clock driven with drift correction; injectable clock/media for tests), `useTimelineHistory` (undo/redo), Editor page at `/app/projects/:id/editor` ("Edit video" on the project page): start screen, preview with scrubber, inspector (scene name, in/out, trim to playhead, mute, move, delete; clip start, track mute, remove; add a project video as a scene), timeline strip (ruler, scenes, audio rows, playhead, drag to reorder), save/start over, unsaved-changes warning, keyboard shortcuts, read-only for viewers.
- Tests: 86 server (+10 timelines: probing, seeding with/without voiceover, default video, validation, cascade, routes + access), 61 client (+17: Timeline model, TimelinePlayer with fake media/clock, editor flows, `formatTimecode`). typecheck/lint/test/build green; production build smoke-tested in headless Chromium (sign-up → WebM upload → offline script + voiceover → seed → split → play across scenes → save).
- Next: 6b overlays with keyframes (add an `overlay` track kind to the schema and render overlays over the preview video), then 6c transitions, 6d auto-zoom from clicks, 6f ergonomics.
- Known issues: the voiceover clip follows source-video time, so after cutting or reordering scenes the user must move it by hand (or the narration drifts from the picture); per-segment voiceover clips on the timeline would fix this and belong with 6d/7. Headless Chromium can't decode H.264, so browser smoke tests should use WebM sources. Switching scenes reloads the `<video>` source, which can stutter briefly between scenes from different files.

### 2026-10-16 — Milestone 5 (AI voiceover) done

- Server libs: `SpeechClient.synthesize` (OpenAI `/v1/audio/speech`, model `TTS_MODEL`) and the `VOICES` list; `FfmpegService.silence` / `changeTempo` / `mixAtOffsets`; `StorageService.removeDir`; `mapLimit` (`lib/concurrency.ts`, TTS runs 4 at a time). `ScriptService.load` for other modules.
